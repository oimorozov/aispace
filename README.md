# aispace

Локальное пространство для связанных AI-задач. У каждого тасклета есть инструкция, отдельная переписка и история результата. Стрелки задают порядок выполнения; независимые задачи работают параллельно.

## Запуск

Backend и Codex запускаются непосредственно на Mac. Нужны Python 3.11+, [uv](https://docs.astral.sh/uv/), Node.js 22.12+, npm и установленный Codex CLI.

```sh
uv sync --all-packages --all-groups
npm ci
npm --prefix frontend ci
npm start
```

Приложение: <http://localhost:8080>. Документация API: <http://localhost:8080/api/docs>.

`npm start` собирает frontend и запускает локальный backend. Он раздаёт готовые статические файлы и API с одного адреса. `Ctrl+C` останавливает backend и его процессы Codex. Docker для работы не нужен. Код frontend и backend раздельный; интерфейс обращается к backend через HTTP API и SSE.

Для подписки ChatGPT откройте «Настройки» → «ChatGPT». При наличии локальной авторизации Codex она используется автоматически; иначе нажмите «Войти через ChatGPT». Вход выполняется на странице OpenAI по предложенному коду. Проверена работа с Codex CLI 0.155.0.

В выборе рабочей папки кнопка «Выбрать в Finder…» открывает стандартное окно macOS. Можно также использовать список каталогов или ввести обычный путь `/Users/...`. Отмена системного окна сохраняет прежний выбор. Кодекс использует выбранную папку и инструменты, установленные на Mac.

Порт и повторную сборку можно настроить:

```sh
npm start -- --port 8082
npm start -- --no-build
```

## Перенос прежних данных из Docker

Если использовалась контейнерная версия, выполните перенос до первого `npm start`:

```sh
python3 scripts/migrate_docker.py
```

Скрипт проверяет отсутствие активных задач, останавливает прежние контейнеры и переносит данные в `.data/`. Сохраняются переписки, настройки, авторизация и сессии Codex. Пути `/host/...` и `/workspace/...` преобразуются в пути Mac. Существующий `.data/` не перезаписывается, исходный Docker-том остаётся резервной копией. Личный `~/.codex` не изменяется.

После переноса `npm start` и `npm run dev` автоматически используют `.data/codex`. Для отдельных команд backend можно указать `AISPACE_CODEX_HOME="$PWD/.data/codex"`. Старый контейнерный стенд остаётся в Compose для миграции и регрессионных проверок.

## Разработка

```sh
npm run dev
```

Приложение: <http://127.0.0.1:5173>. Документация API: <http://127.0.0.1:8000/api/docs>.

`npm run dev` запускает оба приложения. `Ctrl+C` останавливает оба процесса. Для запуска по отдельности:

```sh
uv run --package aispace-backend uvicorn aispace.main:app --host 127.0.0.1 --port 8000
```

```sh
npm --prefix frontend run dev
```

## Использование

1. Откройте «Настройки» и выберите способ подключения: ChatGPT через Codex или API-ключ.
2. В пространстве создайте тасклеты с названиями и инструкциями.
3. Соедините выход одного тасклета со входом другого. Зависимости должны образовывать граф без циклов.
4. Запустите пайплайн. Задачи, у которых выполнены все зависимости, запускаются параллельно в пределах лимита из настроек.
5. Откройте тасклет, чтобы посмотреть результат, продолжить его чат или изменить инструкцию перед следующим запуском.

Стрелка по умолчанию означает ожидание завершения задачи. Передачу её текстового результата можно включить отдельно. Общий контекст пространства добавляется к запросам всех тасклетов.

«Остановить» отменяет все активные запросы и ожидающие задачи текущего пайплайна. Частичные ответы сохраняются. После обновления страницы выполнение продолжается; после остановки самого backend незавершённые запуски отмечаются прерванными. Повторный запуск создаёт новую попытку.

В режиме API используется OpenAI-совместимый Chat Completions API; укажите ключ и модель. По умолчанию адрес — `https://api.openai.com/v1`. Этот режим работает с текстовой перепиской и не читает локальные файлы самостоятельно.

В режиме ChatGPT используется Codex App Server с авторизацией через подписку. API-ключ не нужен; пустое поле модели оставляет выбор по умолчанию в Codex. Использование учитывается в лимитах подписки. Это отдельные чаты Codex, история из веб-интерфейса ChatGPT не импортируется. [Официальная документация авторизации](https://learn.chatgpt.com/docs/auth).

Импорт GitHub issues пока не подключён.

## Рабочая папка и контекст

Выберите рабочую папку проекта в настройках. Тасклеты наследуют её; в редакторе конкретного тасклета можно выбрать другую папку. Реальный путь передаётся Codex как `cwd`, а не только упоминается в тексте запроса. При смене папки создаётся новая сессия Codex; предыдущая переписка остаётся видимой в aispace.

По умолчанию включён доступ «Только чтение». Для реализации изменений выберите «Чтение и изменение в рабочей папке». Команды выполняются с выбранной песочницей Codex на Mac; запросы на расширение прав автоматически отклоняются.

Общие правила проекта удобно хранить в `AGENTS.md`, а в промпте тасклета задавать результат, относительные пути и проверку. Например, при выбранной папке проекта:

```text
Добавь фильтрацию тикетов в frontend/src/components.
Требования к API смотри в docs/api.md.
Сохрани текущий стиль интерфейса. Проверь npm run build.
```

Codex загружает инструкции `AGENTS.md` по правилам своего исполнителя. Выбор папки не означает, что всё дерево файлов целиком отправляется в каждый запрос. [Документация контекста проекта](https://learn.chatgpt.com/docs/agent-configuration/agents-md).

`AISPACE_CODEX_HOME` позволяет задать отдельный каталог состояния Codex, а `AISPACE_CODEX_BIN` — путь к исполняемому файлу. По умолчанию выбор папок охватывает всю файловую систему Mac с учётом прав пользователя. Если требуется ограничить доступный каталог, задайте `AISPACE_WORKSPACE_ROOT` явно.

## Команды исполнителя и остановка

Slash-команды обрабатывает исполнитель, а не сама языковая модель. В режиме Codex aispace поддерживает:

| Команда | Действие |
|---|---|
| `/goal Текст цели` | Установить нативную цель Codex и начать выполнение |
| `/goal` | Показать цель и её статус |
| `/goal pause` | Приостановить цель; при активном пайплайне остановить весь пайплайн |
| `/goal resume` | Продолжить цель через отслеживаемый запуск тасклета |
| `/goal clear` | Удалить цель, сохранив историю чата |
| `/stop` | Остановить весь пайплайн |

Другие slash-команды явно отклоняются. В режиме API команды исполнителя недоступны. Обычные команды вроде `npm test` можно указать в задаче словами: «Выполни npm test и исправь ошибки».

«Остановить всё» доступно в шапке пространства и в редакторе/чате тасклета. Для Codex остановка приостанавливает активную цель, отправляет `turn/interrupt`, ожидает подтверждения, очищает фоновые терминалы и завершает процесс исполнителя. Если исполнитель не отвечает, используется принудительное завершение его группы процессов. Уже сделанные изменения файлов при остановке не откатываются. [Протокол Codex App Server](https://learn.chatgpt.com/docs/app-server).

## Архитектура

```text
aispace/
├── backend/       Python, FastAPI, SQLite, планировщик, API-клиент и Codex
├── frontend/      React, TypeScript, Vite, React Flow
├── e2e/           Проверки интерфейса с локальным тестовым API
├── scripts/       Нативный запуск, разработка и миграция данных
├── pyproject.toml uv workspace
└── uv.lock
```

Frontend взаимодействует с backend через HTTP API и SSE. События обновляют статусы и ответы без перезагрузки страницы. Сохранение данных и выполнение графа не зависят от браузера.

Один backend-процесс управляет планировщиком. Запускайте Uvicorn с одним worker; автоматическая перезагрузка backend прерывает активные запуски.

Данные сохраняются локально в `.data/`; путь меняется переменной `AISPACE_DATA_DIR`. Каталог исключён из Git и контекста Docker-сборки. После миграции состояние Codex и авторизация находятся в `.data/codex`; при новой установке используется локальная сессия Codex. API-ключ и токены Codex не возвращаются в API-ответах и не записываются в localStorage браузера. Ключ защищён правами доступа к локальному файлу, шифрование хранилища не используется.

Приложение предназначено для запуска на `127.0.0.1`: аутентификация для доступа по внешней сети не реализована.

## Проверки

```sh
npm test
```

Команда запускает тесты backend, проверку TypeScript и production-сборку frontend. Тесты используют локальные подмены API, не требуют настоящего API-ключа и не отправляют платных запросов.

Для проверки пользовательских сценариев в Chromium:

```sh
npx playwright install chromium
npm run test:e2e
```

Перед этим остановите `npm run dev`: проверки используют те же локальные порты. Команда сама запускает оба приложения и тестовый API, создаёт отдельную временную базу данных и останавливает процессы по завершении. Личные данные в `.data/` не затрагиваются.

Тот же набор сценариев через Docker Compose и Nginx, включая проверку данных после перезапуска контейнеров:

```sh
npm run test:docker
```

Проверка использует отдельный Compose-проект, порты 8081 и 8766 и собственный том. По завершении удаляются только тестовые контейнеры, образы и том. Запущенное приложение на порту 8080 и его данные не затрагиваются.

```sh
npm run build
```

Результат сборки интерфейса находится в `frontend/dist`.

Проверка настоящего Codex после `codex login`:

```sh
uv run --package aispace-backend python scripts/verify_codex.py
```

Она использует лимиты текущей ChatGPT-подписки, создаёт временную рабочую папку, проверяет чтение файла, продолжение чата, нативную цель и остановку двух выполняющихся команд. Тестовые сессии архивируются; файлы проекта не изменяются. Автоматические pytest и браузерные проверки настоящую подписку не используют.
